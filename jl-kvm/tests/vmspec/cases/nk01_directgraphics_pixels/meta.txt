source: Nokia UI API 1.1 javadoc (S40 DP2.0 SDK 1.1, tools/env/cache/nokia-sdk, not copied into the repo): DirectGraphics (pixel formats and their examples: the 9x9 TYPE_BYTE_1_GRAY array 0xC1 0xF0 ..., the TYPE_BYTE_1_GRAY_VERTICAL examples 1 and 2 with their byte arrays, scanlength and offset in pixels, alpha rules, setARGBColor/setColor relation, polygons use the colour parameter and keep the current colour, exceptions). Byte values and exception names are from the javadoc; the colour of a set bit / gray level (set = black, 0 = white) and the bit expansion of the short formats are UNVERIFIED (both FreeJ2ME and JL-Mod agree on the 1-bit polarity).
notes: UNVERIFIED: polarity of 2/4/8-bit gray (0 = white), expansion of 4/5/6-bit channels by bit replication, alpha of a 1555 pixel (bit set = 255), rounding of the translucent blend (only the channel ranges are compared), rasterisation of polygon edges (only interior and exterior pixels are compared), IllegalArgumentException for a non-multiple manipulation. Oracles (MicroEmulator, FreeJ2ME) are not run for this case: MicroEmulator's DirectGraphics is incomplete (prints "public void drawPixels..."), FreeJ2ME differs on 555/1555.
