## 2. T21 - MIDlet life cycle, JAD / manifest, AMS

* Guest: `javax.microedition.midlet.MIDlet` (full API), package-private `Bridge` (reaches the protected `startApp/pauseApp/destroyApp` for the AMS), `jlkvm.internal.Ams` (ROM-private).
  The VM launches `jlkvm/internal/Ams.run(String className)` as the main thread: it starts the event thread, constructs the MIDlet (state Paused), calls `startApp` (state Active).
* States and order (UNVERIFIED on Nokia; the oracles never pause):
  * host pause: `hideNotify` of the shown Canvas, then `pauseApp()`; host resume: `startApp()`, then `showNotify` + repaint. Both run on the event thread.
  * `notifyPaused()` -> Paused; a later system resume does NOT restart a MIDlet that paused itself; `resumeRequest()` queues `startApp()` on the event thread.
  * `startApp` throwing `MIDletStateChangeException` -> stays Paused; any other exception -> `destroyApp(true)` and exit. `destroyApp(false)` throwing `MIDletStateChangeException` = refused, the MIDlet lives on; `destroyApp(true)` always ends it.
  * `notifyDestroyed()` -> `Runtime.exit(0)` (no `destroyApp`). Lifecycle requests that arrive while `startApp` is still running wait until it returns.
* `getAppProperty`: attributes of manifest merged with JAD (JAD wins), name lookup case-insensitive, `null` key -> NullPointerException. `platformRequest(url)`: host decides (`PlatformServices`: 0 handled, 1 exit first, -1 -> `ConnectionNotFoundException`); `checkPermission`: host policy (1/0/-1).
* JAD / manifest (`Descriptor`, `MidletSuite`): port of JL-Mod's `ru.woesss.j2me.jar.Descriptor` (Apache-2.0) without the Android UI code; continuation lines by leading space (the original broke on a continuation containing ':'), BOM, CR/LF/CRLF; required attributes checked (JAD: Jar-URL, Jar-Size); Name/Vendor/Version of JAD and manifest must agree; `MIDlet-n` -> `Entry(name, icon, class)`; `--midlet N` selects.
* Host API for Android (`AmsHost`): `pause()`, `resume()`, `destroy(boolean)`, `repaint()`, `displaySize(w,h)`, key / pointer methods - every one only calls `Vm.postEvent` (thread-safe). **Not yet wired to an Activity**: the mapping `onPause -> pause()`, `onResume -> resume()` is documented in `AmsHost` and exercised on the desktop with scripted `pause` / `resume` / `destroy` lines (`DesktopHostTest.lifecycleOrder`); checking it on a real Activity is M6 (T35).

## 3. T22 - EventLoop, Display, Canvas (D13)

* One guest thread `event` (`jlkvm.internal.EventLoop`) runs `paint`, `keyPressed/Released/Repeated`, `pointer*`, `commandAction`, `callSerially` runnables, `showNotify/hideNotify`, `sizeChanged`, and the MIDlet pause/resume/destroy callbacks. Per round it runs at most one guest job, then at most one host event (fair).
  Host events come from `Vm.postEvent` (any thread) through the native `EventLoop.next0`, which blocks only the event thread; guest threads post jobs with `EventLoop.post` (native `wake0`). The host never calls guest code.
* Debug assertion (D15, `DebugFlags.ENABLED`): `Vm.runSlice` records the first calling thread as the vm-thread; a guest entry from any other thread logs, counts (`Vm.threadViolations`) and throws `IllegalStateException`; `postEvent/requestExit` stay legal everywhere (`guestEntryFromAnotherThreadIsRejected`).
* Event numbers (`HostEvents` == `EventLoop` constants): 1-3 key pressed/released/repeated (a = code), 4-6 pointer (a,b = x,y), 7 display size (a,b = w,h), 8 repaint all, 20-22 pause / resume / destroy.
* `Display`: `setCurrent` changes `getCurrent()` at once; hideNotify (old), then showNotify (new), then the first paint are delivered on the event thread in order. `Canvas.isShown()` is false inside `showNotify` (MIDP: "prior to being made visible"), true afterwards, false again inside `hideNotify`.
  Repaint: `repaint(x,y,w,h)` requests are coalesced to the union rectangle (the clip of `paint`'s Graphics); `serviceRepaints()` from the event thread paints at once, from another thread blocks until the pending paint is done (returns at once when the Canvas is not shown); an exception in `paint` / any callback is printed with its guest stack and the event thread continues. `callSerially` is FIFO with the other jobs, i.e. after the pending paint, and repaint requests made before it are merged.
* Key codes come from the profile (`keys{}`): Nokia defaults soft -6/-7, select -5, up/down/left/right -1..-4, clear -8, send -10, end -11 (UNVERIFIED, T33). `getKeyCode`, `getGameAction` (arrows and 2/4/6/8/5, 1/3/7/9 = GAME_A..D), `getKeyName` use them. Soft keys with commands (normal mode): left = most important command, right = a BACK/CANCEL/EXIT/STOP command or the second one; consumed (no key events); in full-screen mode (and with no commands) they reach `keyPressed`. A menu for more than two commands is T24.
* Pointer events are dropped when the profile says `pointerEvents: false`; `keyRepeated` only when `repeatEvents`. Key repeat timing (`keyRepeat{delayMs,intervalMs}`) is applied by the host driver (script `key hold`).
* Oracle comparison (`tests/vmspec/cases/ev01_display_order`, MicroEmulator 2.0.4 and FreeJ2ME-Plus; neither is a device, V4):

  | Point | jl-kvm | MicroEmulator | FreeJ2ME | Decision |
  |---|---|---|---|---|
  | setCurrent(A) then (B): order of callbacks | hideNotify(A), showNotify(B) | showNotify(B), hideNotify(A) | same as MicroEmu | RI order; MIDP leaves it open |
  | repaint(); callSerially(R1); repaint(); callSerially(R2) | paint, R1, R2 | paint, R1, paint, R2 | paint, R1, R2 | coalescing is allowed by MIDP |
  | repaint(); repaint(); repaint(5,5,3,3) | one paint, clip = union | same | one paint with the LAST rectangle only | union |
  | Canvas after showNotify | paints by itself | paints by itself | does not | device behaviour |
  | getCurrent() right after setCurrent | new displayable | old one (display events wait for the end of `startApp`) | same | spec: "unlikely to return the new one"; games on devices expect the new one |
  | hideNotify when the MIDlet ends | not called | called | called | UNVERIFIED |
  | display events while `startApp` still runs | delivered | held back until `startApp` returns | same | games with a loop in `startApp` need them |

## 4. T23 - Graphics / Image / Font

* Guest (`Graphics`, `Image`, `Font`): `Graphics` keeps colour, translate, clip (absolute box), stroke, font; every draw native gets `(target handle, colour, clip box, absolute coordinates)`, so the host keeps no per-Graphics state. Anchors and argument checks (IllegalArgumentException / NullPointerException / IllegalStateException / ArrayIndexOutOfBounds) are done in the guest, as are the 8 `drawRegion` transforms' sizes. An `Image` owns a host handle (`peer`), released by the collector when the object dies (`Handles` owner, D8). Canvas painting goes to a persistent back-buffer Image; `Display.present0` hands the finished frame to the host (`PlatformServices.present`).
* `imagesCountInHeap` (profile): when true the guest Image also holds a `byte[w*h*4]`, so the pixel memory is charged to the guest heap, freed by the collector, and a too small heap gives the guest `OutOfMemoryError` (`GraphicsHostTest`). Default false (host memory only). UNVERIFIED which one a Nokia does.
* Common native interface (what host-android has to implement): `jlkvm.host.ui.Surface` (draw primitives with absolute coordinates + clip box, `drawSurface` with the 8 transforms, `drawRgb`, `copyArea`, `getRgb`, `copyRegion`) and `SurfaceFactory` (create / decode / fromRgb / font metrics). The ~30 native keys (`javax/microedition/lcdui/Graphics.fillRect0(IIIIIIIIII)V` ...) are registered once in `MidpNatives`; the full list is the `register` method (descriptors == the `private static native` declarations of `Graphics`, `Image`, `Font`, `Display`, `jlkvm.internal.Device/EventLoop/Ams`).
* `SoftRaster` (pure Java, deterministic: integers, StrictMath only for trigonometry) is the desktop implementation and also usable on Android; PNG: `PngDecoder` (all colour types / depths, tRNS, Adam7); fonts: `BitmapFonts` over `jlkvm/fonts.bin` baked from DejaVu Sans / Sans Mono (`tools/fontgen/BakeFont.java`, licence note next to the resource), sizes 10/13/17 px, bold = +1 px smear, italic = shear, underline; Latin-1, Latin Extended-A, Vietnamese; unknown chars draw `?`. No AWT at run time.
* Rasterisation rules: lines Bresenham incl. both end points, DOTTED = every second pixel; `fillRect` covers `[x,x+w) x [y,y+h)`; `drawRect` covers `x..x+w, y..y+h`; ellipses / round rects / triangles sample pixel centres (triangle edges also drawn); alpha blend `(s*a + d*(255-a) + 127)/255` onto an opaque destination; mutable images are opaque white initially; `drawImage` onto itself reads from a snapshot.
* Oracle comparison of `tests/vmspec/cases/gfx01_graphics` (64 fingerprint / value lines): identical to MicroEmulator on 38, to FreeJ2ME on 36. The differences:

  | Line(s) | jl-kvm | MicroEmulator | FreeJ2ME | Reason |
  |---|---|---|---|---|
  | `dotted` | every 2nd pixel | solid (stroke ignored) | 2 on / 2 off | MIDP leaves the pattern open |
  | `offscreen+empty` | nothing outside the image | differs | differs | only inherited: the step draws on the same image as `dotted` (clipping of off-image rectangles alone matches MicroEmulator, checked separately) |
  | `emptyclip` | 0x0 | negative size (-36x-52) | same | oracle bug |
  | `drawRoundRect / fillRoundRect / drawArc / fillArc / fillTriangle` | own rasteriser | AWT | AWT | edge pixels differ by design |
  | `text` | baked DejaVu bitmaps | AWT fonts | AWT fonts | fonts differ by design |
  | `drawRegion t0..t7` | anchor applied like drawImage | BOTTOM/RIGHT anchor of `drawRegion` off by one pixel (bug: `drawRegion(.., BOTTOM|RIGHT)` lands 1 px right/down; `drawImage` is right) | same as jl-kvm | spec: same anchor rules as drawImage |
  | `drawImage anchors` | exact | exact | differs: its destination keeps an alpha channel, blended pixels carry alpha (`befe7e7e`) and round differently | MIDP: blend onto an opaque surface |
  | `drawRGB alpha / opaque / offset`, `getRGB` | blends | ignores per-pixel alpha | alpha channel in destination | same |
  | `drawImage self` | correct copy (snapshot) | smears (reads while writing) | same | overlap is undefined in MIDP |
  | `iae ...` (anchor 0, BASELINE for images, colour 256, transform 9, drawRegion onto itself) | IllegalArgumentException as the javadoc says | no exception for several | no exception for several | the oracles skip checks |
  | `/gfx/*.png` (RGBA, palette + tRNS, grey, RGB), `createImage` 8 transforms, `getRGB`, clip, translate, fillRect, drawRect, drawLine, exceptions of `createImage/getGraphics/drawString(null)` | identical | identical | identical, except the rgba PNG: FreeJ2ME returns 0 for fully transparent pixels and off-by-one colours for alpha 0x80 (premultiplied storage) | |

* **Android**: not done and not tested in this container. `host-android` has to provide `PlatformServices` (present = blit to the SurfaceView / GLES texture, vibrate, platformRequest via Intent), a `SurfaceFactory` (either `SoftRaster` - same pixels as the desktop by construction - or a Bitmap/Canvas backend moved from JL-Mod; the latter cannot match the software raster bit for bit and needs the M6 comparison), and the Activity wiring of `AmsHost`/keys. The acceptance "same pixel hash on desktop and Android" of T23 is therefore NOT claimed.

## 5b. T22a - java.util.Timer / TimerTask

`vm-classlib/midp/src/java/util/{Timer,TimerTask}.java`: one guest (green) thread per Timer runs the tasks in order of execution time against `System.currentTimeMillis()` (virtual clock in deterministic mode, D14). Semantics of the J2SE/MIDP javadoc: `schedule(task, delay[, period])` = fixed delay (the next time is `start of this run + period`, so a slow run is followed at once, but missed runs are NOT made up), `scheduleAtFixedRate` = fixed rate (grid `first + k * period`, missed runs are caught up), `Date` forms (a past date runs at once, negative time -> IllegalArgumentException), `TimerTask.cancel()` true when it prevented a run, `scheduledExecutionTime()`. `Timer.cancel()` drops all tasks; a task that throws ends the timer thread (uncaught exception) and later `schedule` calls throw IllegalStateException (as for a cancelled timer); a task scheduled twice / cancelled -> IllegalStateException; no `purge()` in MIDP (D9). There is no finalizer in CLDC, so an abandoned Timer thread keeps waiting (the javadoc asks the application to `cancel()`). Tests: vmspec `tm01_timer` (FreeJ2ME = JDK Timer; MicroEmulator's own Timer deviates), `vm-core` `TimerTest` (10 deterministic runs identical, exact times).

## 6. T24 - high-level lcdui (Form, List, TextBox, Alert, Items) and the host screen protocol

**Split (D8, R7):** the MODEL lives in the guest (`javax.microedition.lcdui.*`: all state, all MIDP argument rules and exceptions, selection rules, constraints, commands, listeners). PRESENTATION is the host's: a host shows the current Form / List / TextBox / Alert with its own widgets and reports user actions back as events. The guest never draws these screens, the host never calls guest code (D13).

* **Guest -> host** (`jlkvm.internal.Ui`, natives registered in `MidpNatives`, host interface `jlkvm.host.ui.ScreenHost`): whenever the current displayable becomes visible or its model changes, the event thread sends the WHOLE description once (`Ui.sync0(int[], len, String[], n)`; changes are coalesced: `Displayable.touch()` posts one job). Format (`lcdui.ScreenCodec` writes, `jlkvm.host.ui.ScreenModel.decode` reads, same numbers): `MAGIC 0x4A4C5549, screenId, kind (1 CANVAS 2 FORM 3 LIST 4 TEXTBOX 5 ALERT), flags (bit0 full-screen canvas), title, ticker, commands[cid, type, priority, flags (1 list select, 2 alert dismiss, 4 item default), label, longLabel]`, then by kind: FORM `focusItemId, items[...]`; LIST `choice`; TEXTBOX `text`; ALERT `text, image, alertType, timeout, modal, indicator item?`; CANVAS nothing (the host shows the canvas surface). Strings are indexes into the string table (-1 = null); images are Image handles (`peer`). Item record: `iid, kind (1 string 2 image 3 text 4 date 5 gauge 6 choice 7 spacer 8 custom), label, layout, locked w/h, preferred w/h, minimum w/h, commands[...], kind data`. A CustomItem is painted by the guest into an off-screen Image whose handle is in the record. `ScreenModel.dump()` is the deterministic text form used by tests.
* **Host -> guest** (events through `Vm.postEvent`, `HostEvents.UI_*`, handled in `Display.uiEvent` on the event thread): `UI_COMMAND (screen id, command id)`, `UI_ITEM_COMMAND (item id, command id)`, `UI_CHOICE (item or list id, element, selected)`, `UI_TEXT (item or textbox id)` (the text is fetched by the guest with `Ui.text0(id)` from the host mailbox: latest wins), `UI_GAUGE`, `UI_DATE / UI_DATE_CLEAR`, `UI_CUSTOM (item id, CustomItem event code, parameter)`. The guest applies the change to its model (TextField/TextBox input that violates maxSize or constraints is dropped), THEN calls `itemStateChanged` / `commandAction` on the event thread, so every listener callback is serialised with `paint` / `keyPressed` / `callSerially` (D13). Events for an item or screen that is no longer current are ignored. Ids come from one counter (`Ids`), so a command object keeps its id across screens. Programmatic changes never call a listener; `Item.notifyStateChanged()` posts the call to the event thread. The guest does NOT re-send a change the host itself caused (the widget already shows it).
* **Alert**: the host shows it; `timeout` -> the guest thread dismisses a non-modal Alert (generation counter: a re-shown Alert is not cut short by an old timer). Modal = FOREVER or two or more application commands. With no application command the implicit `DISMISS_COMMAND` (flag 2) is in the command list; its activation calls `commandAction(DISMISS_COMMAND, alert)` and then shows the next displayable (UNVERIFIED order; MIDP says the application may call setCurrent in the listener). `setCurrent(alert, next)` / `getCurrent()` rules as in section 3.
* **List**: IMPLICIT selection calls `commandAction(selectCommand, list)` (default `List.SELECT_COMMAND`; `setSelectCommand` adds the command to the list's commands, `null` = no command). EXCLUSIVE/MULTIPLE lists only change state.
* **Menu for more than two commands (Canvas)**: a normal-mode Canvas with more than two commands: left soft key opens a menu drawn over the canvas by the library (all commands except the one the right soft key takes), up / down move (wrap), select or left soft key runs the command, right soft key or clear closes; the right soft key runs the first BACK / CANCEL / EXIT / STOP command. While the menu is open no key reaches the canvas. For Form / List / TextBox / Alert the menu is the host's concern (it gets the full command list). UNVERIFIED on Nokia devices (V10).
* **Layout:** `getPreferredWidth/Height`, `getMinimum*` are guest ESTIMATES from the font metrics (wrap at the form width; default font), unless locked by `setPreferredSize`. The real layout belongs to the host; MIDP leaves the sizes to the implementation. Form `getWidth/getHeight` = the canvas area of the profile.
* **Ownership rules** (MIDP 2.0 javadoc, checked by vmspec `ui01..ui03`): an item already in a Form/Alert -> `IllegalStateException`; mutable Images given to ImageItem / Choice / Alert are copied; `Spacer` rejects commands and labels; Choice selection rules per type; TextField / TextBox share `TextModel` (constraints NUMERIC/DECIMAL/PHONENUMBER are validated, flags accepted; implementation limit of `maxSize` 5000, UNVERIFIED).
* **Headless host** (`host-desktop` `HeadlessUi`): keeps the last description, executes the script verbs `ui dump|cmd|dismiss|select|text|item N cmd|choice|text|gauge|date|custom` (format in `HeadlessUi`, used in `tests/midlets/scripts/ui.inp`) by posting the events above and updating its own widget state; `HeadlessRunner` prints `# ui ...` dumps. **host-android: NOT done (M6)**: implement `ScreenHost` with real Android views on the UI thread (R7) - build the views from `ScreenModel`, post `HostEvents.UI_*` from view listeners, keep the text mailbox for `UI_TEXT`; pass it to `MidpNatives`.
* Tests: `host-desktop` `UiHostTest` (sample MIDlet `tests/midlets/ui` driven by `ui.inp`; golden `tests/midlets/expected/ui.txt` and `ui-dumps.txt`; every callback on the event thread; stale actions ignored), vmspec `ui01_form_items`, `ui02_choice`, `ui03_text` (spec-only: both oracles are sloppy on these rules, differences listed in each `meta.txt`).

## 6b. T25 - Game API (GameCanvas, Sprite, TiledLayer, LayerManager, Layer)

`vm-classlib/midp/src/javax/microedition/lcdui/game/*`: Java guest on top of `Graphics`; surface == the MIDP 2.0 DB (`game/` is no longer in `pending`).

* **GameCanvas**: an off-screen buffer (initially white) the size of the canvas; `getGraphics()` returns a NEW Graphics on it each call (MIDP javadoc); a buffer size change (full-screen toggle) creates a new white buffer (UNVERIFIED). `flushGraphics([x,y,w,h])` does nothing when the canvas is not shown, otherwise `repaint` of the clamped region + `serviceRepaints` (the paint runs on the event thread, D13; `paint(g)` draws the buffer). **Key states**: the library sees key events first on the event thread through the ROM-private hook `jlkvm.internal.KeyTap` (Canvas keeps a package-private `tap`, installed by GameCanvas through `jlkvm.internal.Access`, so no extra public member exists). Latching: press sets the key's bit in `latched` and `down`, release clears `down`; `getKeyStates()` returns `latched` and restarts it from `down` (a press+release between two calls is seen once, a held key by every call). Bits = `1 << gameAction`. `suppressKeyEvents = true` swallows only keys that have a game action (others, e.g. `*`, still reach `keyPressed`).
* **Sprite**: frames of a sheet, frame sequences (empty -> IllegalArgumentException, member out of range -> ArrayIndexOutOfBoundsException, `null` restores the raw order), the 8 transforms with the formulas of the reference code; `setTransform` keeps the reference pixel where it is (position changes), `setImage` with another frame size keeps the reference pixel and resets the collision rectangle, more or equal frames keep sequence and frame, fewer reset them. Collision: rectangle test in painter coordinates on the TRANSFORMED collision rectangle; pixel level checks every pixel of the intersection with the inverse transform against a lazily built one-bit-per-pixel alpha mask (built on the first pixel-level query of an image / tile set, so a game loop allocates nothing afterwards); a pixel is opaque when alpha = 255 (both oracles; UNVERIFIED). Mutable source images are NOT copied (both oracles; UNVERIFIED), so a later change of a mutable image shows (the mask is not refreshed).
* **TiledLayer**: cells in an `int[]`, animated tiles (negative indices, IndexOutOfBoundsException for a bad animated index, as the oracles), `setStaticTileSet` (fewer tiles than before clears every cell and deletes the animated tiles), paint draws only the cells that touch the clip with `drawRegion`. **LayerManager**: index 0 on top; `append` / `insert` of a layer already in the manager first remove it (the index of `insert` is checked after the removal), `setViewWindow`, `paint(g, x, y)` restores translate and clip; a view window of Integer.MAX_VALUE is clipped at 2^24.
* **No allocation in the drawing paths (PLAN DoD 7, D15)**: `Graphics.drawImage/drawRegion/copyArea` no longer allocate an `int[2]` per call (`placeX/placeY`), `drawString/drawSubstring` and `Font.stringWidth/substringWidth` hand the String to the host (natives `Graphics.drawStr0`, `Font.strWidth0`) instead of `toCharArray()`, `drawChar` reuses a one-char buffer, and `Canvas.paintNow` reuses its screen Graphics (`reset()`). Measured with the sample game (`tests/midlets/game`): 200 frames of LayerManager.paint (Sprite + TiledLayer) + three collision tests + `flushGraphics` allocate 0 bytes of guest heap (`freeMemory` before / after; the profiler `--profile` shows no per-frame allocation site). `GameHostTest` asserts it.
* **Menu**: unchanged. Tests: vmspec `gm01_sprite_model`, `gm02_collision` (with a self check of the pixel test against the rasteriser for the 8 transforms), `gm03_tiled_layer`, `gm04_layer_manager`, `gm05_sprite_paint` (checksums identical to FreeJ2ME; differences with the oracles in each `meta.txt`), `host-desktop` `GameHostTest` (key-state latching, suppress, flush, allocation).

## 8. T26 - RMS (javax.microedition.rms)

**Split (D8):** the MIDP rules are guest Java (`RecordStore`, `RecordEnumerationImpl` in `vm-classlib/midp/src/javax/microedition/rms`), bytes + quota + persistence are the host's (`host-common` `jlkvm.host.rms.RecordStorage`, natives `jlkvm.host.RmsNatives` <-> ROM-private `jlkvm.internal.Rms`). `MidpNatives` takes a `RecordStorage` (default `MemoryRecordStorage`); host-desktop uses `FileRecordStorage` (`HeadlessRunner --rms-dir DIR`, `Options.records` / `Options.rmsDir`), host-android will use the same class over `Context.getFilesDir()` (pure java.io).

* **Suite identity** = `MIDlet-Vendor` + `MIDlet-Name` (manifest + JAD). Stores of a suite live in `<root>/<escaped suite>/<escaped store name>.rms`; one file per store, rewritten through `.tmp` + rename after every change (a crash leaves the previous complete file); a broken file is skipped and listed in `FileRecordStorage.problems`.
* **Quota (profile `rms{quotaBytes, storeOverheadBytes, recordOverheadBytes}`, defaults 262144 / 16 / 8, ALL UNVERIFIED, T33 gives them a source tag):** `getSize()` = store overhead + sum(record data + record overhead); the quota is per SUITE (all its stores share it); `getSizeAvailable()` = quota - everything the suite's stores occupy (0 at least). `addRecord` / `setRecord` that would exceed it throw `RecordStoreFullException` and change nothing (growing a record counts only the growth); creating a store needs `storeOverheadBytes`. Deleting frees the room.
* **MIDP rules in the guest:** store name 1..32 characters (`IllegalArgumentException`; `null` -> `NullPointerException` like both oracles), case sensitive; authmode other than 0/1 -> `IllegalArgumentException`; `authmode`/`writable` of `openRecordStore(name,true,auth,w)` apply only when the store is created; the same store opened again returns the SAME object and counts references (`closeRecordStore` as many times; the last one closes it, drops the listeners and the kept-updated enumerations; later use -> `RecordStoreNotOpenException`, an extra close too); `deleteRecordStore` of an open store -> `RecordStoreException`, of a missing one -> `RecordStoreNotFoundException`; `listRecordStores()` = `null` when the suite has no store; record ids start at 1 and are never reused (also after a restart); `getRecord` of a record without data returns `null`, `getRecord(id,buf,off)` throws `ArrayIndexOutOfBoundsException` before copying when the buffer is too small; `addRecord/setRecord(null,0,0)` = empty record, bad offset/length -> `ArrayIndexOutOfBoundsException`, `null` with numBytes > 0 -> `NullPointerException`; version increases on add / set / delete (and `setMode`), `lastModified` is the guest clock (virtual clock in deterministic mode, D14).
* **Other suites (`openRecordStore(name, vendor, suite)`):** only a store with `AUTHMODE_ANY` (else `SecurityException`); missing store / unknown vendor or suite -> `RecordStoreNotFoundException`; when `writable` is false, add / set / delete / `setMode` throw `SecurityException`; `setMode` is for the owner only. Naming your own suite gives the same object as the one-suite open.
* **Listeners** (`RecordListener`) run synchronously on the thread that made the change, after the change, user listeners in registration order (a listener registered twice is added once; an exception of a listener propagates to the caller). They are guest code, so they never run on a host thread (D13).
* **Enumerations:** a snapshot of ids built when created / `rebuild()`: the filter sees each record (an empty record gives `byte[0]`), the comparator orders a stable merge sort (PRECEDES / EQUIVALENT / FOLLOWS by sign), without comparator the order is ascending id. The cursor sits BETWEEN elements: `nextRecord` then `previousRecord` returns the same record, `previousRecord` at the start and `nextRecord` at the end -> `InvalidRecordIDException`; the data is read when returned (a record deleted since the build -> `InvalidRecordIDException` after the cursor moved; `null` for an empty record, like `getRecord`). `keepUpdated(true)` rebuilds now and after every change of the store (the position stays, clamped); `keepUpdated(false)` stops; after `destroy()` every method throws `IllegalStateException`. UNVERIFIED on devices: position after a rebuild, order for equal keys is by id (stable).
* **JL-Mod saves:** `JlModRmsImport.importDir(dir, storage, suite)` reads the data directory of J2ME-Loader / JL-Mod (`<name>.rsh` header "MIDRMS" 3.0, `<name>.<id>.rsr` records; format taken from `app/.../rms/impl/AndroidRecordStoreManager` + `RecordStoreImpl`), keeps version / lastModified / lastRecordId / authmode / writable, applies no quota, skips broken files (listed in `Result.problems`); `HeadlessRunner --import-jlmod-rms DIR`. Caveat: JL-Mod removes the characters of `FileUtils.ILLEGAL_FILENAME_CHARS` from the FILE name only; the store name comes from the header, so two names that differ only in such characters were already one store there.
* **Tests:** vmspec `rms01_store` (spec-only; both oracles crash on corner cases, differences in `meta.txt`), `host-common` `RecordStorageTest` (accounting, quota, files, escaping, broken file, import), `host-desktop` `RmsHostTest` (stores outlive a run, sharing between suites `tests/midlets/rms` + `rmsb`, quota from a profile `tests/midlets/rmsq`, JL-Mod import).

## 9. T26b - GCF of MIDP 2.0 (`javax.microedition.io`) and `javax.microedition.pki`

* **Interfaces** (exactly the stub DB, generated from it): `HttpConnection`, `HttpsConnection`, `SocketConnection`, `ServerSocketConnection`, `UDPDatagramConnection`, `CommConnection`, `SecureConnection`, `SecurityInfo`, `pki.Certificate`; classes `PushRegistry`, `pki.CertificateException`. With T20 (`Connector`, `StreamConnection`...) `javax.microedition.io` and `pki` are no longer in `pending`.
* **Policy first** (T20, unchanged): per scheme the profile says `deny` (`SecurityException`), `offline` (`IOException`, the default) or `allow`; `comm` / `file` / `resource` / `storage` skip it. Only after `allow` does `Connector.open` look for the handler `jlkvm.internal.io.<scheme>.Protocol`; no handler -> `ConnectionNotFoundException`.
* **Handlers: only `http`** (`midp/src/jlkvm/internal/io/http/Protocol`): `https`, `socket`, `serversocket`, `datagram`, `ssl`, `comm`, `sms`... have the interfaces but NO handler (allow -> `ConnectionNotFoundException`). Setup / Connected / Closed states of the javadoc: method (GET, HEAD, POST; anything else -> `IOException`), request properties (case-insensitive, replaced), output stream (collected in memory) are accepted only in Setup; the request goes out at the first call that needs the response (code, message, header, length, type, input stream); a GET with a body is sent as POST (like `HttpURLConnection`, UNVERIFIED on devices); redirects are NOT followed (3xx reaches the application); 4xx / 5xx are not exceptions; default `User-Agent: Profile/MIDP-2.0 Configuration/CLDC-1.1` (from the profile properties) unless the application sets one; `getFile()` is `null` when the URL has no path, `getPort()` 80 by default, `getHeaderField(n)` / `getHeaderFieldKey(n)` count the header fields without the status line and give `null` beyond the end, `getHeaderFieldDate` parses RFC 1123 dates. The connection can be closed while its input stream is still read.
* **Host:** `host-common` `NetNatives` (natives of ROM-private `jlkvm.internal.Net`) + `net.HttpTransport` (`JavaHttpTransport` over `HttpURLConnection`, response held in memory up to 16 MiB, timeout 30 s). The native re-checks the policy for `http` (`allow` only) before it creates a thread, so a host with `offline`/`deny` never opens a socket (`NetHostTest.deniedHostNeverOpensASocket`). The request runs on a worker thread and parks only the calling guest thread (`AsyncBlocker`). `MidpNatives.httpTransport(...)` replaces the transport (tests, Android).
* **PushRegistry:** no push delivery in this runtime. Arguments are checked (null -> `NullPointerException`, unknown MIDlet class -> `ClassNotFoundException`), then `registerConnection` / `registerAlarm` -> `ConnectionNotFoundException` (the javadoc's answer for "not supported"); `listConnections` is empty, `getMIDlet` / `getFilter` give `null`, `unregisterConnection` false.
* **pki:** `Certificate` is an interface only (no https handler yet, so nothing creates one); `CertificateException(Certificate, byte)` / `(String, Certificate, byte)`, `getReason()`, `getCertificate()`, all reason constants.
* **Tests:** `host-desktop` `NetHostTest` (MIDlet `tests/midlets/net`, JDK `HttpServer` on the loopback interface, the JAD attribute `Test-Url` carries its address): offline -> `IOException` for every scheme, deny -> `SecurityException`, no socket opened when not allowed, allow -> status line, headers (by name, index, int, date), type / length, body read after the connection is closed, 404 without exception, 302 not followed, HEAD, POST with body and `Content-Type`, GET with body, state errors, connection refused -> `IOException`, schemes without handler -> `ConnectionNotFoundException`, bad URL / port -> `IllegalArgumentException`; vmspec `io01_gcf_midp` (constants, hierarchy, PushRegistry, CertificateException, Connector under the runner's default profile).

## 10. T27 - MMAPI (`javax.microedition.media`), tone sequences, RTTTL/RTX, JSR-135 controls

**Layers (D10).** MIDP 2.0 subset of MMAPI (`Manager, Player, PlayerListener, Control, Controllable, MediaException, control.ToneControl, control.VolumeControl`; surface == `midp-2.0.json`) is in `rom-midp.jar`. The JSR-135 parts that are not in the MIDP DB, `control.MIDIControl`, `control.RateControl`, `control.TempoControl`, are a THIRD layer `vm-classlib/jsr135/src` -> `rom-jsr135.jar` (`:vm-classlib:buildJsr135Rom`, base = CLDC + MIDP merged). A profile gets them only with `"apis": [..., "jsr-135"]` (host-desktop `RomLayers`); without it the classes do not exist for the game (checked by `MediaHostTest.jsr135ControlsExistOnlyWhenTheProfileDeclaresThem`) and `getControl("MIDIControl")` gives `null`.
Signature source of the three interfaces: `tools/api-sigs/db/jsr-135-extra.json`, extracted with `api-sigs extract` from the compiled interfaces of JL-Mod (`app/src/main/java/javax/microedition/media/control`, Apache-2.0, the repo's own app module; no phoneME/OpenJDK/Oracle text used). No JSR-135 stub jar and no JSR-135 javadoc are in the repo, so these signatures are UNVERIFIED against the JSR; the semantics (rate = milli-percent, 100000 = normal; tempo = milli-beats per minute; MIDI status/data ranges) are from memory of the JSR and marked UNVERIFIED below. The game that needs them (Oregon Trail, `docs/games-api-scan.md`) only uses MIDIControl and TempoControl.
Not done of JSR-135 (not in `jsr-135-extra.json`): `PitchControl`, `StopTimeControl`, `MetaDataControl`, `RecordControl`, `VideoControl`, `GUIControl`, `FramePositioningControl`, `TimeBase`, `protocol.DataSource`, `Player.setTimeBase/getTimeBase`, `Manager.createPlayer(DataSource)`, capture/video, `device://midi`.

**Split (D8).** The MMAPI rules are guest Java; the host only makes sound.

| Piece | Where |
|---|---|
| `Manager`, `BasePlayer` (state machine, listeners, loop count, controls, VolumeControl), `TonePlayer`, `ClipPlayer`, `Events` | `vm-classlib/midp/src/javax/microedition/media`, `.../jlkvm/internal/media` |
| Tone sequence compiler `ToneSeq`, RTTTL parser `Rtttl`, event list `Seq` | `.../jlkvm/internal/media/tone` (java.lang only: also compiled by `host-common` tests) |
| ROM-private natives `Audio` <-> `host-common` `AudioNatives` | one `AudioDevice` per host |
| `jlkvm.host.audio.AudioDevice` (interface), `RecordingAudioDevice` (headless: log + deterministic PCM checksum), `ToneSynth` | `host-common` |
| MIDIControl / TempoControl / RateControl implementation | `vm-classlib/jsr135/src/jlkvm/internal/media/ext`, found by `Class.forName` when `config0(CFG_JSR135)` (= profile apis has `jsr-135`) |

**Profile `media{contentTypes[], protocols[], tone}`** (`DeviceProfile.mediaContentTypes/mediaProtocols/mediaTone`, `ProfileLoader`): what `Manager.getSupportedContentTypes/getSupportedProtocols` answer and `createPlayer` accepts. Defaults (ALL UNVERIFIED, T33 gives them a source): types `audio/x-tone-seq, audio/midi, audio/sp-midi, audio/x-wav, audio/mpeg, audio/amr, audio/x-rtttl, text/x-rtttl`; protocols `device, http, https, file, resource`; `tone` true (`Manager.playTone`, `device://tone`). `getSupportedContentTypes("device")` = only `audio/x-tone-seq`; an unknown protocol / type gives an empty array (never null). Locator rules: null -> `IllegalArgumentException`; no `scheme:` or a scheme not in `protocols` (e.g. `capture://`) or `device://` other than `tone` -> `MediaException`; other schemes are opened with `Connector` (so the network policy of T20/T26b applies: offline -> `IOException`), the content type comes from the connection (or the file extension: `.mid .wav .mp3 .amr .rtx .rtttl`). `createPlayer(InputStream, type)`: null stream -> `IllegalArgumentException`; `type == null` -> sniffed from the first bytes (MThd, RIFF/WAVE, ID3 / MPEG sync, `#!AMR`, tone-seq header, RTTTL text with two colons) else `MediaException`; a type not in the profile (after lower-casing, dropping `;params` and a few aliases: `audio/mid`, `audio/x-midi`, `audio/wav`, `audio/mp3`...) -> `MediaException`.

**Player (MIDP 2.0 javadoc of `Player`/`PlayerListener`; the javadoc is not in the repo, chosen behaviour is listed here and in the vmspec `meta.txt`).**
* States 100/200/300/400/0. `realize`/`prefetch`/`start` do the missing steps; `stop` on a non-started player, `start` on a started one, `realize` on a realized one are no-ops; `deallocate` of a STARTED player stops it (STOPPED event) and goes to REALIZED; `close` is idempotent. `IllegalStateException`: any method on a CLOSED player (`getState` is the exception), `getContentType/getControl(s)/setMediaTime` while UNREALIZED, `setLoopCount` while STARTED. `setLoopCount(0)` -> `IllegalArgumentException`, negative = forever. `getControl(null)` -> `IllegalArgumentException`; short name = package `javax.microedition.media.control.` assumed.
* Time is in microseconds. `setMediaTime` clamps to `0..duration`, returns the value set, works while started (playing continues from there). `getDuration()` = `TIME_UNKNOWN` (-1) while UNREALIZED or when unknown (host clips without a readable length); tone sequences / RTTTL: sum of the notes (one pass). At the end of the media (after all loops) the state is PREFETCHED, media time = duration, `END_OF_MEDIA(Long)` is sent. A `start` after the end plays from the beginning (UNVERIFIED; the javadoc leaves it open).
* **Events** (`PlayerListener`): STARTED(Long media time), STOPPED(Long), END_OF_MEDIA(Long), CLOSED(null), VOLUME_CHANGED(VolumeControl) are sent; DURATION_UPDATED / ERROR / DEVICE_* are never sent. They are queued by the call that causes them and delivered in order on ONE guest thread (`jlkvm.internal.media.Events`, started at the first event), never inside the call that caused them and never from a host thread (D13, checked by `mm01_player_states`, `MediaHostTest`, `vm.threadViolations == 0`). A listener that throws is reported on System.err and delivery goes on. Listeners are copied at the event; a listener added twice is called twice (UNVERIFIED). UNVERIFIED: `close()` of a started player sends STOPPED before CLOSED; VOLUME_CHANGED only when level or mute actually changes.
* **VolumeControl** (every player): level 0..100 (default 100, UNVERIFIED), `setLevel` clamps and returns the level set, `setMute` keeps the level. The tone player multiplies each note's volume by the effective level at the moment the note starts; a clip player passes the effective level (0 when muted) to the device.
* **ToneControl** (players of `device://tone` and `audio/x-tone-seq` streams; not RTTTL): `setSequence` compiles at once (`IllegalArgumentException` for null / invalid), `IllegalStateException` in PREFETCHED/STARTED/CLOSED. A `device://tone` player with no sequence is silent with duration 0 (lenient, UNVERIFIED). Tone-seq streams and RTTTL data are parsed at `realize()`; an invalid one gives `MediaException` there.
* **Tone sequence format** (`ToneSeq`): VERSION 1 first; TEMPO 5..127 (bpm = 4 x), RESOLUTION 1..127, SET_VOLUME 0..100, tones (note 0..127 or SILENCE, duration 1..127 units, unit = `60 000 000 / (tempo x resolution)` microseconds), BLOCK_START n .. BLOCK_END n (0..127, defined once before use, no nesting, may use earlier blocks), PLAY_BLOCK n, REPEAT m (2..127) followed by a tone or PLAY_BLOCK. TEMPO / RESOLUTION / SET_VOLUME may appear anywhere between events (UNVERIFIED: the javadoc grammar has them in a header); events inside a block are interpreted again at every PLAY_BLOCK (tempo / volume changes persist after it); the expanded list is limited to 65536 events.
* **RTTTL / RTX** (`.rtx`, `audio/x-rtttl`, `text/x-rtttl`, `audio/rtttl`): parsed by `Rtttl` in the GUEST (same code for T32's Smart Messaging ringing tone, deterministic, unit-testable by compiling it as plain Java in `host-common`; the host would need a copy per platform) and played as tones by a guest thread; NO decoder / ffmpeg is involved (the JL-Mod log `mobile-ffmpeg: ....rtx: Invalid data found` cannot happen). Format accepted: `name:d=D,o=O,b=B:notes`, case-insensitive, blanks / line breaks / BOM ignored, name of any length or empty, defaults section may be empty or partial and in any order (defaults d=4, o=6, b=63 - UNVERIFIED on a Nokia), d in {1,2,4,8,16,32}, o 0..8, b 1..1000, notes `[d]letter[#][.][o][.]` (a..g, h = b, p = pause; the dot lengthens by half before or after the octave), empty items ignored, anything else -> error. MIDI note = `12 x (octave + 1) + semitone` (A4 = 440 Hz). Durations in integer microseconds: whole note `240 000 000 / bpm`, note `whole / d`, dotted x 3 / 2. Tests: `host-common` `ToneParsersTest` (defaults, octave, duration, dots, bpm, case, long names, BOM, errors), vmspec `mm02_tone`, `MediaHostTest`.
* **Playing** (`TonePlayer`): a guest thread per run sleeps against `System.currentTimeMillis()` with an absolute schedule (no drift; virtual clock in deterministic mode) and calls `Audio.tone0(note, ms, volume)` per note; a pause calls nothing. The host device sounds it for `ms` ("a later call replaces it"). `Manager.playTone(note, ms, volume)` is one `tone0` call and returns at once (IAE for note outside 0..127 or duration <= 0, volume clamped).
* **Clips** (`ClipPlayer`): other types are handed to the host. Data goes to the host in 1 KiB chunks (`Audio.stage0`, never held in the 2 MiB guest heap; limit 16 MiB), becomes a host "source" (`source0`), `realize` opens a device clip (`AudioDevice.open`; the device refuses -> `MediaException`), `deallocate` closes the clip but keeps the source, `close` frees both. `start` = `play0(clip, loops, run)` plus a guest thread parked in `await0(clip, run)` (`AsyncBlocker`): the device calls `AudioDevice.Listener.ended` on any thread, that only completes the blocker, the guest thread then sends END_OF_MEDIA through `Events`. `stop`, `close`, a new `start` release the older waiter (run numbers). Media time of a started clip = device position.

**JSR-135 controls** (`jsr-135` layer; `BasePlayer.midiCapable()`: tone players, RTTTL and `audio/midi`/`audio/sp-midi` clips):
* `MIDIControl` -> `AudioDevice.midiShort/midiLong` (one synthesiser per device, not per player: UNVERIFIED). Ranges (UNVERIFIED, from memory of the JSR): channel 0..15, volume 0..127, bank 0..16383, program 0..127, status byte 0x80..0xFF without 0xF0/0xF7, data bytes 0..127 -> `IllegalArgumentException`. `setChannelVolume` = CC 7; `setProgram` = CC 0 / CC 32 (bank MSB / LSB) + program change; `getChannelVolume` -1 until set; `getProgram` -> `MediaException` until set; `longMidiEvent` returns the length sent; bank queries unsupported (`isBankQuerySupported` false, the four query methods throw `MediaException`).
* `TempoControl` / `RateControl` (one object answers both names): rate in milli-percent (100000 = normal, range 10000..1000000), tempo in milli-beats per minute (default 120000; tone sequence: its own TEMPO x 4000); values are clamped to the range (UNVERIFIED: the JSR says "closest supported value"; a non-positive tempo leaves the tempo unchanged). A tone player scales the length of the notes still to come (`MmApi135`: half tempo = twice as long, measured on the virtual clock); a clip player asks the device (`AudioDevice.tempo/rate`).

**Headless desktop host.** `RecordingAudioDevice` logs `t=<virtual ms> tone 72 250 100`, `open 2 audio/midi 14 bytes duration=-1`, `play 2 loops=2 at=0`, `midi 144 60 100`, ... and renders every tone through `ToneSynth` (8 kHz mono, deterministic) into a sample count + checksum (`pcmSamples()`, `pcmChecksum()`), enough to test states and timing. It parses the duration of PCM WAV; other formats have an unknown duration. The end of a clip is simulated by the script verb `audio end N` (`HeadlessRunner`, `Options.audio` to pass a device). A device that sounds the tones/clips for real on the desktop (javax.sound) is optional and NOT written.
**Android: NOT done (M6).** `host-android` must implement `AudioDevice`: Sonivox / TinySoundFont of JL-Mod (`app/src/main/cpp/mmapi_tsf/TinySoundFont` is vendored; JL-Mod's `MIDIControlImpl`/`AndroidPlayer` show the native side) for tones, MIDI and `midiShort/midiLong`, `MediaPlayer`/`AudioTrack` for WAV/MP3/AMR; `Listener.ended` may be called from any thread; pass it to `MidpNatives.audioDevice(..)` (host-desktop: `DesktopHost.setAudioDevice`). Latency of the tone/MIDI path and polyphony of the Android synthesiser are unmeasured.
**Other UNVERIFIED / not done:** the default content type and protocol lists; the default volume level 100; `Manager.createPlayer(locator)` over `http`/`file` is only as good as the Connector handlers (T26b: `http` only; `file`, `resource` have no handler yet so those locators give `ConnectionNotFoundException`); MIME of `.mmf`/`.imy`/Nokia `.nrt`; a profile `media.contentTypes` cannot name a type for which the device has no decoder (the device refuses at realize). `Smart Messaging` OTT (T32) will reuse `Rtttl`; `com.nokia.mid.sound` (T28) can sit on `Audio`/`TonePlayer`.
**Tests:** `host-common` `ToneParsersTest`; vmspec `mm01_player_states` (69 lines: states, exceptions per state, loops, media time, events and their thread, VolumeControl) and `mm02_tone` (Manager rules, playTone, tone sequence durations / errors, RTTTL durations) - both spec-only; `host-desktop` `MediaHostTest` (MIDlets `tests/midlets/mmapi` + `mmapi135`, script `tests/midlets/scripts/mmapi.inp`, golden `tests/midlets/expected/mmapi135.txt`). `tests/midlets/build.sh` compiles a MIDlet with a `jsr135` marker file against the JSR-135 interfaces of the ROM layer (`J2MEC_EXTRA` of `tools/env/j2mec.sh`).
